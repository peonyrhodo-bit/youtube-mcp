# Фактическое состояние проекта

Срез: 2026-11-19. Это **частичный аудит**, не итоговая оценка соответствия ТЗ.

## Подтверждено
- Три основных Render-сервиса: `youtube-mcp`, `site-insight-engine`, `ai-youtube-system`. Все free, основные ветки `main` с автоматическим деплоем.
- Дополнительный Render-сервис `site-insight-engine-pr21-isolated`, ветка `fix/director-research-operation-contract`, autoDeploy выключен. Владелец просит удалить лишний сервис; удаление ещё не выполнено.
- В Supabase есть данные об исследованиях и роликах, но на момент предварительной проверки таблица `recommendations` не содержала строк; это **симптом**, не установленная первопричина.
- В `director_runs` наблюдались `stale_timeout` и `ReadError: [Errno 11] Resource temporarily unavailable`; причины ещё не доказаны.
- В логах `youtube-mcp` 2026-11-19 13:58 UTC были повторные ошибки `UnicodeEncodeError` при `search.list`. Нужна проверка входных данных и участка кодирования; не считать причиной всех сбоев без трассировки.
- В `ai-youtube-system/scheduler.py` интервал по умолчанию 21600 секунд (6 часов). Не доказано, что этот скрипт используется работающим сервисом.
- `scheduler/wakeup.py` содержит внутрипроцессную очередь сигналов, которая не переживает перезапуск. Её влияние на реальный цикл не доказано.
- В Supabase обнаружены таблицы без RLS; это риск безопасности. Нельзя включать RLS вслепую: можно нарушить доступ приложения.
- `docs/director-acceptance-test-plan.md` содержит непомеченные как пройденные приёмочные проверки.

## Не установлено
- Какие конкретно ошибки являются первопричинами отсутствия итоговых рекомендаций.
- Полная цепочка от пробуждения до исследования, сохранения и отображения результата.
- Фактическая нагрузка RAM/OOM, частота ошибок, точные лимиты и причины.
- Реальная конфигурация всех запланированных запусков и переменных окружения (значения секретов не извлекать).
- Полное покрытие требований ТЗ директора 3.0 и состояние всех пользовательских сценариев.
- Безопасность использования тестового сервиса для приёмочных испытаний.

## Правило статуса
Любое утверждение «работает» должно сопровождаться проверяемым свидетельством; гипотезы и не проверенные сценарии не считать завершёнными.
