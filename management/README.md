# Управление проектом — единая точка входа

Дата начала: 2026-11-19. Статус: аудит, без изменений работающего кода.

## Неприкосновенные источники
- `/тз` — генеральное ТЗ. Не изменять, не переименовывать, не удалять.
- `/тз директор 3,0` — ТЗ текущего этапа. Не изменять, не переименовывать, не удалять.

Приоритет текущего этапа — **Директор 3.0**, не преждевременная реализация всей системы видеопроизводства.

## Где находится система
- `peonyrhodo-bit/youtube-mcp`: YouTube MCP, исходные ТЗ и управляющие документы.
- `peonyrhodo-bit/site-insight-engine`: ядро Директора, исследование, аналитика, веб-интерфейс, Supabase.
- `peonyrhodo-bit/ai-youtube-system`: связующий API/оркестрация.
- Render: три основных бесплатных веб-сервиса; четвёртая тестовая копия `site-insight-engine-pr21-isolated` подлежит удалению по желанию владельца после проверки отсутствия нужных данных/использования.
- Supabase: проект `site-insight-memory`.

## Порядок работы
1. Аудитор устанавливает ожидаемый результат по ТЗ и собирает факты из кода, логов, базы и тестов.
2. Каждой подтверждённой проблеме соответствует ограниченная задача для Codex с критериями приёмки.
3. Codex работает в отдельной ветке и открывает PR; не меняет ТЗ и посторонние компоненты.
4. Проверка PR включает тесты, риски памяти/квоты/стоимости, регрессию и фактический результат.
5. Только после приёмки изменения попадают в `main`; production-деплой требует отдельной оценки риска.
6. После каждого этапа обновляются `STATE.md`, `BACKLOG.md` и `DECISIONS.md`.

## Постоянные ограничения
- Только бесплатные сервисы и зависимости; не инициировать платные операции.
- Ограниченная RAM на Render: замерять потребление и избегать неограниченных загрузок данных.
- Render может засыпать; внешний будильник будит примерно каждый час, но иногда запуск пропускается. **Не считать каждый пропуск доказательством дефекта кода. Не исправлять механизм пробуждения без изменения приоритетов владельцем.**
- Без согласования не удалять данные, не менять конфигурацию безопасности/доступа, не запускать платные или расходующие квоту операции, не публиковать видео.
- Не объявлять проблему исправленной по одному успешному тесту или наличию функции.
- Документы из истории и старые планы не являются автоматически действующими указаниями.

## Что делать в новом чате
Прочитать оба неизменяемых ТЗ, затем этот файл, `STATE.md`, `BACKLOG.md`, `DECISIONS.md`; сверить с актуальными GitHub/Render/Supabase. Не полагаться на память переписки.
